Why it exists

It grew because runs failed

April 2025: code pasted from a Grok chat. October 2025: the first independent AI auditor. 26 November 2025: the workflow file is born at 284 lines. Today it is 11,009 lines across 93 commits, and each addition is dated to the run that needed it.

Lines in the workflow file, from git · growth is rules added after failures, not features

Each major rule links back to the failure that required it. Gates carry the run that needed them: “added 2026-07-03, Run 108”, “operator-caught 2026-08-18”. Around it grew a system: 26 reviewer and builder roles, 22 reference skills, 3 testing harnesses, and 1,000 commits to the workflow folder alone.

Who reviews

Five reviews on the plan, seven on the code, then one run separately

  • Different models, different review roles, run in parallel: two Claude Opus reviewers, one OpenAI Codex, one xAI Grok, and the coordinating model's own verdict. Each is told: you are the auditor, not a rubber stamp.
  • Some reviewers cannot see the others' findings. The data-flow tracer works from the plan and the code alone. A validator removes any line number or value that does not exist in the real code.
  • The separate round runs outside the workflow. A brief is built from pinned code versions, 12 patterns of secrets are removed, a 28-check gate refuses a dirty brief, and I paste it into a separate OpenAI Codex session myself. No timeout auto-proceeds.

Where it stops

A claim without evidence stops the run

The claim
“I edited the file.”
What the workflow does
The recorded changes show nothing changed. The claim is false. Back to implementation.
The claim
“The plan uses this piece of data.”
What the workflow does
That data does not exist in the database. Blocked before a line is written.
The claim
Transaction-critical code, no record that the tests ran.
What the workflow does
No deploy. The test record must exist and match this run.
The claim
The external brief contains a server address.
What the workflow does
Hard block. The brief never leaves the machine.
The claim
Fewer than four of five reviewers finished.
What the workflow does
Deployment blocked. A thinner panel is not a panel.
The claim
The external verdict is not back yet.
What the workflow does
Wait. There is no timeout. The point of the gate is the independent opinion.

Memory

Whatever breaks once becomes a rule the next time

Run

a task goes through the loop

Handover

a save-file that survives the AI losing its memory mid-run

Review

the transcript is scored against a rubric, with quoted evidence

Gap

anything that should have fired and did not gets an ID and a severity

Rule

the fix is written into the workflow; a text check confirms it was added, later runs test whether it works

Archive

plan, code changes, review decisions and file fingerprints are frozen; the architecture document is rewritten from the code
